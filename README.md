# Lay Language AI

Lay Language AI is a Streamlit prototype that rewrites complex medical language into patient-friendly plain English. It compares the same input across the original `google/flan-t5-small` model and a fine-tuned version trained on curated medical rewrite pairs.

## What The App Does

1. A user pastes a medical note, diagnosis, report sentence, or short clinical phrase.
2. The app sends the text to the base model.
3. The app sends the same text to the fine-tuned model.
4. The app displays both outputs side by side.

## Data

The training data is stored in:

```text
data/raw/medical_rewrites.jsonl
```

It contains 1,000 curated rewrite examples. Each row is a JSON object with:

- `category`: the medical area represented by the example
- `medical_text`: the original clinical or medical wording
- `plain_language`: the patient-friendly rewrite

Example:

```json
{
  "category": "Otolaryngology",
  "medical_text": "Flexible laryngoscopy demonstrates mild vocal fold edema without lesions or airway compromise.",
  "plain_language": "A small camera exam of the throat shows mild swelling of the vocal cords. No growths are seen, and the airway does not look blocked."
}
```

The data includes 50 samples from 20 fields of medicine to ensure exposure to as wide a range of data as possible. The fields are listed as follows:

- Cardiology
- Dermatology
- Emergency Medicine
- Endocrinology
- Gastroenterology
- General Surgery
- Hematology
- Infectious Disease
- Nephrology/Urology
- Neurology
- Obstetrics/Gynecology
- Oncology
- Ophthalmology
- Orthopedics
- Otolaryngology
- Pediatrics
- Psychiatry
- Pulmonology
- Radiology
- Rheumatology

This data was generated by prompting GPT 5.5 with a small few-shot approach using real patient records and lay translations.
Patient records used in the prompt were provided with the consent of the individuals involved and no real patient records or private health information are used within the AI generated dataset available in this repo.
    
## Model And Training Approach

This project uses a full supervised fine-tuning approach of a smaller (77M parameter) LLM.

The base model is:

```text
google/flan-t5-small
```

This is a small instruction-tuned text-to-text Transformer model. The project fine-tunes it as a sequence-to-sequence rewrite model:

```text
medical note prompt -> patient-friendly rewrite
```

Training code lives in:

```text
scripts/train.py
```

For each example, the model input is built with this instruction. The same prompt format is also used at inference time for both the base model and the fine-tuned model, so the app comparison focuses on the effect of fine-tuning rather than different prompt wording:

```text
Rewrite this medical note in patient-friendly plain English.
Explain medical jargon briefly and preserve the original meaning.

Medical note: [medical text]

Patient-friendly rewrite:
```

The target output is the paired `plain_language` rewrite from the dataset.

The training loop uses:

- Hugging Face `AutoTokenizer`
- Hugging Face `AutoModelForSeq2SeqLM`
- PyTorch `Dataset` and `DataLoader`
- AdamW optimizer
- the model's built-in sequence-to-sequence loss

After training, the fine-tuned model and tokenizer are saved to:

```text
models/lay_language_ai_model/
```

## Local Setup

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
python -m pip install -e ".[dev]"
```

## Prepare The Data

Run preprocessing:

```bash
python scripts/preprocess.py
```

This reads:

```text
data/raw/medical_rewrites.jsonl
```

and writes:

```text
data/processed/train.jsonl
```

You can also run setup without training:

```bash
python setup.py
```

## Train The Model

Train with the default settings:

```bash
python scripts/train.py
```

The default command fine-tunes `google/flan-t5-small` and writes the trained model to:

```text
models/lay_language_ai_model/
```

You can adjust training settings:

```bash
python scripts/train.py --epochs 12 --batch-size 2 --learning-rate 0.0001
```

Or prepare data and train in one command:

```bash
python setup.py --train
```

Training downloads the base model from Hugging Face the first time it runs. Runtime depends on hardware, but this small dataset/model is intended to train quickly on a laptop.

## Run Command-Line Inference

After training, test a rewrite from the terminal:

```bash
python scripts/inference.py "Flexible laryngoscopy demonstrates mild vocal fold edema without lesions or airway compromise."
```

Expected behavior:

- `Base Model` often stays closer to the original medical wording.
- `Fine-Tuned Model` should produce clearer patient-friendly language.

## Launch The Streamlit App

Run:

```bash
streamlit run main.py
```

Then open the local URL Streamlit prints, usually:

```text
http://localhost:8501
```

If running locally with stricter browser/network settings, this also works:

```bash
streamlit run main.py --server.address 127.0.0.1 --server.port 8501
```

The app requires the fine-tuned model directory to exist at:

```text
models/lay_language_ai_model/
```

If that directory is missing, run:

```bash
python scripts/train.py
```

## Deployment Notes

For Streamlit Community Cloud, the repo must contain:

- `main.py`
- `requirements.txt`
- the data files
- a reachable trained model artifact or a model-loading strategy that works at deployment time

The current full fine-tuned model contains a large `model.safetensors` file. If Git LFS bandwidth is unavailable, Streamlit Cloud may fail during source checkout before the app starts. In that case, host the model somewhere else, use a smaller adapter artifact, or retrain/download the model during deployment.

## Risks, Ethics, And Evaluation

This is an educational prototype, not a medical advice system. Important risks include:

- hallucinating medical details
- changing the original meaning
- over-simplifying uncertainty
- producing misleading reassurance
- reflecting bias from the limited training examples
- encouraging patients to rely on AI instead of a clinician

Evaluation should consider both clarity and faithfulness. A useful before/after comparison asks:

- Is the fine-tuned output easier to understand?
- Does it preserve the original medical meaning?
- Does it avoid adding facts not present in the note?
- Would a patient know this is informational and not medical advice?
